# Upgrading to Laravel AI Engine 3.0

Version 3.0 removes the compatibility surfaces deprecated throughout the 2.x
release line. The model-driven runtime, resource providers, scoped knowledge
index, entity focus, assistant response schema, and realtime tool APIs remain
supported.

## Removed compatibility surfaces

| Removed in 3.0 | Required replacement |
| --- | --- |
| Agent chat request field `async` | `execution_mode=sync|async|auto` |
| Agent chat request field `rag` | `use_rag` |
| `LaravelAIEngine\Facades\AIEngine` | `LaravelAIEngine\Facades\Engine` |
| `AIEngineFake::requests()` | `AIEngineFake::calls()` |
| `ai-agent.ai_native.enabled` | Remove the setting; AI-native is always active |
| Raw `agent_context:{session}` cache fallback | Scoped `AgentContextRepository` keys |

Unknown Agent Chat fields are ignored by Laravel request validation. A 3.0
client that still sends `async` or `rag` therefore receives canonical default
behavior rather than compatibility translation. Update payloads before
deploying the package.

## Host migration checklist

```text
async=true                 -> execution_mode=async
async=false                -> execution_mode=sync (or auto when intended)
rag=true|false             -> use_rag=true|false
AIEngine::...              -> Engine::...
$fake->requests()          -> $fake->calls()
ai-agent.ai_native.enabled -> remove the setting
```

Clear or wait out legacy unscoped agent-context cache entries before upgrading.
Version 3.0 never reads or deletes those raw keys.

## Deliberately retained surfaces

- `prompt_json` planner transport remains until native tool transport is proven
  across every supported provider.
- Provider shortcut methods such as `Engine::openai()` remain convenience APIs.
- `/api/v1/ai/mcp/tools/{tool}/call` and
  `/api/v1/ai/realtime/tools/dispatch` remain distinct because their approval,
  provider-event, and realtime-output semantics differ.
- Provider-tool runs and agent runs remain distinct lifecycle resources.

## Verify the cutover

The versioned snapshot at `resources/compatibility/3.0.json` records all six
removals and the retained routes:

```bash
php artisan ai:compatibility --json
php artisan ai:compatibility --fail-on-deprecated
```

Both commands succeed on 3.0 and report `deprecated_count: 0`.
